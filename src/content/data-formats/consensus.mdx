Our <AppLink href="https://github.com/Blockchain-Technology-Lab/consensus-decentralization">consensus-decentralization</AppLink> tool expects one file per ledger, named `<project_name>_raw_data.json` (e.g. `bitcoin_raw_data.json`), in newline-delimited JSON — one JSON object per block, per line. We expect the same shape regardless of ledger:

```json
{
  "number": "507715",
  "timestamp": "2018-02-05 04:54:34 UTC",
  "identifiers": "<field identifying the block producer, e.g. a coinbase parameter, extra_data, or pool ticker>",
  "reward_addresses": "<address(es) that received the block reward, comma-separated if there are multiple>"
}
```

Not every field is meaningful for every ledger, for example, Tezos has no `identifiers` field, so it's left out entirely rather than sent empty. Get as close to this shape as your node/crawler naturally supports, and we'll work through any remaining nuances with you as they come up.

Every entry's `timestamp` is UTC. Most ledgers format it as `yyyy-mm-dd hh:mm:ss UTC`; some raw samples (e.g. Cardano) use ISO 8601 (`yyyy-mm-ddThh:mm:ss`, no suffix) instead — either is fine, so just match whatever your own node/crawler naturally produces.
